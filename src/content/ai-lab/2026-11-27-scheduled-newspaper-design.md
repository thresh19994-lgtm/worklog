> AI가 지시서 원문을 바탕으로 쓴 초안입니다. `[...]` 부분은 본인이 직접 채우고 다듬습니다. 공개판 자동 업로드는 아직 운영 전이며, 아래 검증은 사이트 쪽 장치만 확인한 결과입니다.

## 문제

매주 일요일 AI 예약 작업이 게임 업계 신문과 AI 신문을 만들어 준다. [신문을 만든 이유와 구성 — 직접 작성]

이 신문을 사이트에도 올리고 싶었다. 그런데 원본은 나를 위한 문서라서 다음이 섞여 있다.

- "내 작업에 적용", "지난 과제"처럼 개인 학습 맥락
- 주가 표와 강세론·약세론 (공개하면 투자 권유로 오해될 수 있다)
- 실명 인물 평가, 해고·실패 사례 (명예훼손·채용 인상 위험)
- 뉴스 원문 인용 (저작권)

게다가 올리는 주체가 사람이 아니라 무인 예약 작업이다. 웹 문서 안에 숨은 지시(프롬프트 인젝션)에 속아 다른 파일을 바꿀 수도 있다.

## 선택지

| 결정할 것 | 선택지 A | 선택지 B |
|---|---|---|
| 공개판 만들기 | 원본에서 민감한 부분을 지운다(차단 목록) | 허용한 섹션만 새로 쓴다(허용 목록) |
| 안전장치 | AI 지시문에만 의존 | 지시문 + 자동 검사 + 저장소 권한 |
| 머지 | 사람이 매주 확인 | 검사를 통과하면 자동 |

## 결정과 이유

1. **허용 목록으로 새로 쓴다.** 지우기 방식은 하나만 빠뜨려도 샌다. 허용 목록은 적힌 섹션 외에는 처음부터 쓰지 않는다.
   - 게임 신문: 헤드라인 3선의 [사실]·[왜 중요한가], 장르 × 개념, 출처
   - AI 신문: 3줄 브리핑, 헤드라인의 [사실]·[왜 중요한가]·[다른 시각], 활용 랩, 출처
   - 인용은 공개판 전체에서 1문장 이하, 출처 바로 옆에
2. **AI를 믿지 않는 장치를 겹친다.**
   - 금지어 검사(`npm run check`): "내 작업에 적용", "매수", "목표가" 같은 단어가 신문 파일에 있으면 실패한다. 예약 작업에서 한 번, GitHub Actions에서 한 번, 두 번 돈다. 금지어 목록은 파일로 따로 두어 나중에 추가할 수 있다.
   - 경로 검사: `claude/news-*` 브랜치의 PR이 신문 폴더 밖의 파일을 하나라도 바꾸면 실패한다. 인젝션으로 다른 파일을 건드려도 머지되지 않는다.
   - 저장소 룰셋: main에 직접 push 금지, PR과 검사 통과가 필수다. 워크플로 권한은 읽기 전용이고 비밀값을 쓰지 않는다.
   - 검사가 실패하면 PR을 만들지 않고 알림에 "보류(사유)"만 남긴다.
3. **사람 확인은 처음 4주만.** 매주 PR 두 개를 머지하는 일은 결국 형식이 된다. 자동 검사를 1차 관문으로 두고, 4주 동안 깨끗하면 자동 머지로 넘긴다.
4. **신문은 격리한다.** 홈·RSS·sitemap·태그 목록에서 빼고 검색엔진 색인을 막는다(noindex). 글 위에 "Claude가 수집·요약한 자동 생성 문서" 배지를 단다.
5. **날짜는 한국 시간으로.** 일요일 아침 KST는 UTC로 토요일이라, 시간대를 지정하지 않으면 파일 날짜가 하루 어긋난다.

## 검증

사이트 쪽 장치는 실제로 시험했다.

- 금지어("GGC", "내 작업에 적용", "매수", "목표가")와 iframe 태그, 이벤트 속성, 자바스크립트 링크를 넣은 가짜 신문 파일 → 검사가 10건을 잡고 실패했다. (이 글도 처음에 그 태그 이름을 그대로 적었다가 같은 검사에 걸렸다.)
- main에 직접 push → 룰셋이 거부했다.
- 신문 글은 sitemap과 RSS에 0건, 글에는 noindex가 붙었다.

아직 남은 것: 예약 작업에서 수동으로 한 번 돌려 push·PR 생성·검사 실패 시 중단을 확인하는 일. [운영 후 결과 — 직접 추가]

## 전후 비교

| | 처음 생각 | 지금 설계 |
|---|---|---|
| 공개판 | 원본에서 지우기 | 허용 섹션만 새로 쓰기 |
| 마지막 방어선 | AI 지시문 | 금지어 검사 2회 + 경로 검사 + 룰셋 |
| 사람의 일 | 매주 확인 | 처음 4주만 확인 |
| 노출 범위 | 사이트 전체 | /archive 안에만, 색인 제외 |

## 배운 점

- 자동화에서는 "AI에게 하지 말라고 하기"보다 **하지 못하게 만들기**가 먼저다.
- 지우는 방식(차단 목록)보다 **쓸 것만 정하는 방식(허용 목록)**이 새는 곳이 적다.
- 사람 확인 단계는 오래 두면 형식이 된다. 기간을 정해 두고 자동 검사로 넘기는 편이 정직하다.
